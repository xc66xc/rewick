# ZPAY 部署与配置

此改动只新增独立 ZPAY 渠道，默认关闭。保留微信与支付宝原有渠道。

## 部署

1. 按顺序执行 SQL21、`backend/sql/22_zpay_api_qr.sql`（已经执行的不要重复执行，数据库时区 Asia/Shanghai）。SQL22 保存客户端 IP 和一次性下单标记，并停用旧 submit.php 配置；不会自动改写地址。
2. 部署新版 backend、admin，并更新 `deploy/server/nginx.conf`：移除 ZPAY 浏览器收银台入口，通知使用不包含查询参数的专用访问日志。
3. 如使用返回页，部署更新后的 `landing/payment/result.html`（通用付款提示，不用于判定到账）。
4. 分发新版桌面端后，在管理端「支付设置 → ZPAY」填写并保存启用。

## 管理端字段

- 商户 PID、商户密钥：来自 ZPAY 商户后台；密钥只写，加密持久化，不进入客户端。
- 收款方式：支付宝 alipay 或微信 wxpay；首版每份启用配置选择一种，桌面统一显示 ZPAY。
- API 下单地址：`https://zpayz.cn/mapi.php`
- 查询地址：`https://zpayz.cn/api.php`（不要手动拼 act/pid/key 参数）
- 通知地址：`https://api.junshi.icu/api/v1/payments/zpay/notify`
- 返回地址：`https://junshi.icu/payment/result`
- CID：可不填，指定时按供应商格式填写。

Demo 旧域名 z-pay.cn 也可显式配置；不自动替换域名或补接口路径。保存仅校验配置格式，不代表商户实际开通成功。

## 订单行为

后端使用 mapi.php multipart API 下单，设备 pc，clientip 从受信任代理传递的客户端地址采集并持久化；桌面根据 qrcode 本地生成二维码。只返回 payurl/img 而没有 qrcode 时明确报错，不抓取页面或自动切换流程。通知验签后查单，核实商户、方式、订单、金额和交易号再幂等增加面试时长。

每个本地订单只能尝试一次 API 下单。超时、进程中断或结果不明确时保留订单供后续查单，重复点击不会重新向渠道下单；如无法获得二维码，可取消后重新购买。此策略优先避免重复下单，不保证所有网络故障后能恢复二维码。

用户已允许 ZPAY 本地取消：取消/15分钟窗口到期仅关闭本地入口并允许新单，不代表第三方链接失效。旧单晚到付款仍按旧套餐到账一次。已提交的关闭订单在30天内每5分钟进入后台补偿；以后仍支持手动查单及通知到账。退款保持人工登记，不调用 ZPAY 退款接口。

## 验收

使用商户实际允许的小额套餐人工验收：桌面二维码扫码、通知可达、查询到账、重复通知不重复入账、取消后付款能到账。独立支付宝仍用浏览器支付。自动测试只使用模拟供应商，不发生真实支付。
